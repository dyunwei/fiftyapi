# 邮件邀请用户

管理员在“团队成员 → 添加成员”填写邮箱、显示名称与额度。系统发送一次性设置密码链接，用户设置密码后用邮箱登录；不发送明文密码。用户也可在登录页自助注册，填写邮箱、真实姓名和密码，初始额度为 0。

管理员和普通用户的登录密码均为 **8–72 字节**。用户 API Key 仍为系统生成的高熵随机密钥，不是 8 位密码。

## 页面配置

管理员打开「系统设置 → 邮件配置」，填写公共访问地址、SMTP 主机、端口、发件地址、用户名、密码/授权码及加密方式，勾选启用后保存。保存立即生效，不需要重启。然后填写测试收件邮箱，点击「发送测试邮件」；测试使用已保存的配置，不发送成员邀请，每个来源 IP 每分钟最多 3 次。SMTP 接受不等于收件箱已投递，请确认收件情况。

网页配置优先于部署环境变量。关闭启用会停止邀请邮件，即使环境变量仍有 SMTP 配置；「恢复环境变量配置」删除网页保存的配置，重新采用进程启动时的环境配置。环境变量本身变更仍需重启。

密码不返回页面，只显示是否已配置。留空保持原密码，明确勾选清除才会删除。配置整体使用现有主密钥加密存入数据库；备份数据库时仍须单独保存原主密钥。审计只记录配置更新操作，不记录参数或密码。配置损坏时不会静默回退发送邮件。

公共访问地址须为用户可访问的 HTTP 或 HTTPS 源站，不带子路径、参数或片段。支持内网 IP、主机名和端口，例如 `http://192.168.1.10:8080`；HTTP 部署保持 `FIFTYAPI_COOKIE_SECURE=false`。

## 环境变量配置（兼容）

未保存网页配置时，可在部署环境或 Docker Compose 的 `.env` 设置：

```dotenv
FIFTYAPI_PUBLIC_URL=https://your-gateway.example
FIFTYAPI_SMTP_HOST=smtp.your-provider.example
FIFTYAPI_SMTP_PORT=587
FIFTYAPI_SMTP_FROM="FiftyAPI <sender@your-domain.example>"
FIFTYAPI_SMTP_USERNAME=your-smtp-user
FIFTYAPI_SMTP_PASSWORD=your-smtp-password-or-app-password
FIFTYAPI_SMTP_TLS=starttls
```

这些是占位符，需替换为自己的邮件服务参数。`PUBLIC_URL` 是收件人能访问的本项目 HTTP 或 HTTPS 源站，不带子路径、参数或片段，内网地址也可使用。SMTP 发件地址必须符合邮件服务商的要求；服务商可能需要单独的 SMTP 授权码。

`starttls` 要求服务器支持 STARTTLS，通常配合 587；隐式 TLS 使用 `tls`，通常配合 465。不会因 TLS 失败退回明文。`none` 只允许 localhost/127.0.0.1/::1，供本机模拟测试使用。

Docker 配置后执行 `docker compose up -d --build`，使新环境生效。二进制不会自动读取 `.env`，需将变量注入进程环境后再运行。不要把邮件密码提交到 GitHub 或发到聊天中。

未配置 SMTP 时服务仍可启动、原用户仍可登录；页面的邮件邀请不可用，可在系统设置中补充配置。部分 SMTP 参数缺失、发件地址无效或公共 URL 不合规时拒绝启动，避免生成无法使用的链接。

## 管理员操作

1. 添加成员，填写邮箱、可选显示名称、5 小时与每周额度，点击“发送邀请”。
2. 列表显示待设置密码和邮件状态。SMTP 接收邮件不代表收件箱一定成功投递，请同时检查垃圾邮件和邮件服务商的投递记录。
3. 邮件未确认发送时，账号保留，管理员修正邮件配置后点击“重新发送邀请”，不用重复创建用户。
4. 重新发送会立即作废旧链接，新链接有效期 24 小时。正常发送后 1 分钟内限制重发；发送失败可立即重试。
5. 已设置密码的用户忘记密码，也可通过重新发送邀请来重新设置；原密码在新链接被使用前仍可登录。

管理员看不到邀请令牌或当前密码。没有邮箱的既有用户名账号继续按原方式登录和管理；新邀请的账号使用邮箱作为登录标识。默认不批量给现有用户发邮件。

## 用户操作

邮件链接打开专用设置密码页面，输入两次至少 8 位的密码。成功后跳转到登录页，再用邮箱和新密码登录；之后可在个人设置修改密码。

链接只能使用一次。过期、重发后旧链接、已消费链接及停用账号的链接均不可使用；停用会撤销未完成的邀请。遇到无效链接，请联系管理员重发。

设置或修改密码会撤销已有网页登录会话；不会自动撤销用户已有的 API Key。API Key 可在用户页面单独撤销。

## 存储和日志

- 邀请令牌为 32 字节随机值的 URL-safe 编码，数据库仅保存 SHA-256 摘要。
- 链接中的令牌放在 URL fragment，页面读取后立即从地址栏移除，再通过同源 POST 提交；不是查询参数。
- 密码仅以 bcrypt 哈希持久化；邮件正文不含密码。
- 请求日志、审计和发送状态不存邮件正文、链接令牌、SMTP 密码或原始 SMTP 错误内容。
- 邀请与密码激活在数据库事务中处理，重复/并发消费只有一次成功。
- 不记录邮件正文到日志，也不依赖公网邮件服务完成自动化测试。

## 接口与验证

| 接口 | 用途 |
| --- | --- |
| `GET /api/admin/settings/email` | 管理员读取脱敏配置、来源与是否已保存密码 |
| `PUT /api/admin/settings/email` | 保存加密配置；空密码保留，`clear_password=true` 明确清除 |
| `DELETE /api/admin/settings/email` | 恢复环境变量配置 |
| `POST /api/admin/settings/email/test` | 使用已保存配置发送测试邮件，body 为 `email` |
| `GET /api/admin/invitations/config` | 管理员读取是否已配置邮件，不返回 SMTP 凭据 |
| `POST /api/admin/invitations` | 邮箱、显示名称、两个额度，创建用户并发送邀请 |
| `POST /api/admin/users/{id}/invitation` | 管理员重发邀请/设置密码链接 |
| `POST /api/invitations/check` | POST token，检查链接，不消费令牌 |
| `POST /api/invitations/accept` | POST token/password，一次性设置密码 |

自动化覆盖 SMTP 本机投递、发送失败重试、过期/重发失效/停用、并发消费、权限、邮箱登录、8 字节密码和手机页面。真实 SMTP 服务的配置与收件箱投递需由部署方验证。

升级到此版会自动执行数据库迁移 004，建议沿用既有升级流程先备份。原有用户的密码、会话和 API Key 在升级回归中确认保留；不要用旧版本程序直接打开升级后的数据库。

[手机设置密码页面预览](screenshots/email-invitation.png)。

新邀请成员的 5 小时和 7 天预算默认各为 $100，可在发送前修改，包括设为 0。自助注册为 $0；首次创建的管理员及新迁入用户各窗口默认 $100，现有用户不变。详见 [sub2api 迁移](sub2api-migration.md)。
