# 从 sub2api 迁移用户、Key 和上游账号

首次创建管理员时选择「从 sub2api Docker 迁移」，即可进入网页四步向导：导出旧站数据 → 上传迁移文件 → 检查并导入 → 验证与开始使用。网页包含命令、文件传输说明、权限规则、失败原因和下一步操作，无需先阅读本文。管理员创建后会自动登录；刷新或重新登录后会继续未完成的引导，上传文件需重新选择。完成或跳过初始化向导后，常规管理页面不再提供迁移入口，导入接口也会关闭。迁移范围是用户、原 Key 和受支持的账号，不是数据库整站恢复。

## 默认预算

| 新用户来源 | 5 小时预算 | 7 天预算 |
| --- | ---: | ---: |
| 自助注册 | $0 | $0 |
| 管理员邀请（可调整） | $100 | $100 |
| sub2api 迁入用户 | $100 | $100 |
| 首次设置的管理员 | $100 | $100 |

两个预算都是美元周期使用上限，不是一次性余额；所有 Key 和供应商共享。旧站余额、套餐、已用量不参与换算，迁入用户从新窗口开始。现有 FiftyAPI 用户和预算不变。邀请接口省略预算时使用 $100，显式传入 0 仍保持 0。

## 1. Docker 一键导出（网页默认方式）

在运行旧站 Docker 的宿主机上执行网页提供的一条命令：

```sh
curl -fsSL https://raw.githubusercontent.com/dyunwei/fiftyapi/main/scripts/migrate-sub2api.sh | sudo bash
```

[migrate-sub2api.sh](../scripts/migrate-sub2api.sh) 是自包含的 Bash 脚本，不下载其他程序，不要求宿主机安装 Python 或 psql，也不安装依赖。它逐步检查 Docker、查找 PostgreSQL 容器、复用容器凭据只读导出，并打印文件完整路径。多个数据库容器时会提示选择；必须选择旧站数据库容器，不能选择 sub2api 应用容器。它不停止服务、不改写源数据库，也不自动上传数据。

输出默认是新建的 `/tmp/fiftyapi-sub2api-XXXXXX.json`，权限 0600。通过 sudo 运行时会将文件归属交还给调用 sudo 的用户。源标识根据 Docker 引擎、容器名和数据库名自动生成，同一源环境重复导出保持一致。脚本不显示密码、令牌或完整 Key。迁移包上限为 31 MiB、5000 用户、20000 Key、1000 账号、1000 代理，超过限制会失败，不会截断数据。

GitHub 访问失败时，可从网页直接下载当前安装包内嵌的脚本，上传到旧服务器后执行：

```sh
sudo bash migrate-sub2api.sh
# 自定义 PostgreSQL 容器；不需要交互选择
sudo bash migrate-sub2api.sh --container my-postgres
```

按网页说明选择文件。浏览器在另一台电脑时，使用已有 SSH/SFTP 工具将文件下载到浏览器电脑；浏览器就在服务器本机时可直接选择该文件。上传后页面展示数据数量、停用/跳过原因和权限转换选项，确认前不会保存数据。正式切换时停止旧站应用请求和令牌刷新，保持 PostgreSQL 运行，重新导出最终文件，再在网页确认迁移。

迁移文件包含密码哈希、完整 Key、上游令牌和代理密码；通过私有渠道传输，迁移结束后删除。页面不会把文件写入浏览器存储。

### 高级工具

外置数据库仍可使用 [Python 导出工具](../scripts/export-sub2api.py)，配合宿主机 Python 3、psql 及标准 PostgreSQL 连接环境变量。密码放在私有 `.pgpass` / `PGPASSFILE` 中。原 Docker 模式也保留：

```sh
python3 scripts/export-sub2api.py --docker \
  --source my-sub2api-production \
  --output /tmp/sub2api-migration.json
```

Python 工具的 `--source` 需为该旧数据库的稳定唯一标识，重试时沿用，不同源库使用不同值。网页的一键 Bash 流程自动生成源标识，不需要填写。常规用户无需使用高级工具。

## 2. 预览与确认

1. 首次初始化选择迁移并创建管理员后，在向导中选择文件，点击「预览迁移」。预览不会保存用户、Key 或账号，不访问上游，也不刷新令牌。
2. 检查跳过项、停用项和权限转换规则。网页默认勾选将包含旧分组、IP 白名单/黑名单、独立额度、限流预算或有效期的 Key 转换为 FiftyAPI 的全局模型权限和成员预算；取消勾选则保持这些 Key 停用。转换会移除原限制，包括未来有效期。旧站已停用或已过期的 Key 即使勾选也保持停用。
3. 正式切换前，停止旧站应用的请求、管理写入和令牌刷新任务，重新导出最终文件并预览。此前预演应只做预览，不要同时运行两套服务刷新同一份 OAuth 授权。
4. 勾选停止旧站的确认项，点击「确认迁移」。用户和 Key 在一个事务中保存；账号独立保存，某个账号失败不撤销已完成的其他项目。页面逐项显示结果，可重新上传原文件补齐未完成项。

权限转换选项只影响首次插入的 Key。重复导入不会启用已停用或撤销的 Key。如果首次未转换，之后需要保留停用状态，或由成员新建 FiftyAPI Key 并修改客户端；再次勾选不会覆盖已有状态。

## 3. 验证与切换

点击「验证并同步已导入账号」，检查失败项；此操作会联系上游，并可能刷新令牌。API Key 网关的手工模型列表同步仅检查本地配置，不代表已验证真实调用权限。确认「模型与价格」中的模型和价格：未定价模型不可调用，旧分组模型别名、OAuth 账号模型映射及高级路由不自动复现。

使用成员原邮箱和密码登录，并用原 Key 完成一个实际请求后，再切换原域名或修改客户端服务地址。域名、协议和模型名称保持兼容时客户端可沿用原配置；否则修改地址或模型名，Key 无需更换。原管理员迁入后是普通成员，不会获得 FiftyAPI 管理权限。

切换后保留旧站备份并停止其后台刷新。若需回退，先停止 FiftyAPI；已经轮换的 OAuth 刷新令牌未必还能用于旧站，需要另行处理，不能假定旧备份中的令牌仍有效。

## 支持范围与冲突处理

- 用户以旧站邮箱作为登录账号，原 username 用作显示名称。支持兼容的 bcrypt 密码哈希；双因素认证用户及不兼容密码（例如部分第三方登录账号）跳过，避免绕过原认证要求。
- 原 Key 加密保存，认证按原值的哈希匹配；支持 16–128 字节可见 ASCII Key。新建 FiftyAPI Key 的格式不变。Key 所属用户迁移失败时不导入该 Key，不按邮箱猜测归属。
- 用户通过 `source + 旧用户 ID` 记录迁移关系；邮箱/登录名与无关现有用户冲突时跳过，不合并或重置密码。重复导入保留已有身份、密码、启停状态和预算，只补充尚不存在的 Key。
- 支持 Claude/Anthropic、OpenAI/Codex、Antigravity OAuth，保留令牌、有效期、适用的客户端/工作空间 ID，以及 Antigravity project ID。
- 支持 Anthropic 和 OpenAI 的 `apikey` / `api_key` 账号，转为 HTTPS API Key 网关；OpenAI 启用 Chat/Responses，Anthropic 启用 Messages。支持显式、无通配符的模型映射。其他类型（Gemini CLI、Bedrock、service account、cookie、影子账号等）不在首版范围，逐项跳过。
- 关联代理必须存在、启用且未过期；支持 HTTP、HTTPS、SOCKS5、SOCKS5H。代理缺失或不兼容时跳过账号，不自动改为直连。不迁移代理的过期切换和备用代理策略。
- 上游账号保留停用/已过期状态；并发限制上限为 100。优先级保留在 `clamp(旧优先级, 0, 100)` 范围内，两边均为数值较小者优先。同名或相同授权的账号跳过，保留现有配置。
- 不迁移余额、套餐、历史用量、价格、分组、用户平台权限、旧会话、MFA 密钥、邮件/系统配置、自定义请求头及其他高级策略。迁入成员采用 FiftyAPI 现有的全局可用模型权限和预算规则；管理员需评估原用户级权限差异。

管理接口：`POST /api/admin/migrations/sub2api`，需要管理员会话、CSRF、尚未完成的初始化迁移向导和 JSON。请求为 `{ "data": 迁移包, "preview": true/false, "accept_key_policy": false }`。请求上限 32 MiB；响应只包含逐项状态及统计，不含凭据。

## 导入后提示账号或密码错误

使用原邮箱登录，并检查该成员是否启用、是否成功迁入。导入会原样保存兼容的 bcrypt 哈希，不会设置统一密码。重复导入保留 FiftyAPI 当前密码；如果与本次导出不同，预览会明确提示。哈希不同也可能只是同一密码使用了不同盐，不能单凭哈希差异判断明文密码改变。确实无法登录时，由管理员重置密码，或核对可信旧站的原密码记录后恢复；不要自动覆盖所有用户密码。

网页登录表单在提交时读取输入框的实际值，兼容未触发 input 事件的密码管理器自动填充。升级前已打开的旧页面请强制刷新或使用隐身窗口，确保加载新版本页面。

### 密码哈希的传递与写入

网页只解析 JSON，不对 `password_hash` 重新加密；接口解码为字符串后直接绑定到 SQL 参数。写入事务会逐字节回读校验，不一致则回滚本批用户和 Key。成功导入的审计摘要记录 `password_hash_preserved=true`，不记录哈希原文。初始化网页回归测试同时校验文件、HTTP 请求、SQLite 中的哈希相同，并验证原密码能登录。此校验不自动修复既有数据库，也不覆盖本地修改过的密码。
