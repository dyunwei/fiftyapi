# 请求日志与结算异常

普通用户查看自己的日志；管理员查看全部。按请求 ID、模型 ID、HTTP 状态及时间范围筛选。默认每页 20 项，可选择 10/20/50/100；显示总数及当前页，支持前后翻页。筛选和每页条数变更会回到第一页，翻页与结算处理保留筛选。列表按时间、请求 ID 降序稳定排序；持续有新请求时可刷新更新列表。

Codex Responses 的 `response.completed`、Claude Messages 的 `message_stop` 是流式响应的完成标记。网关处理完成标记后结束上游读取，不再等待 HTTP 连接关闭；完成响应成功写入并刷新后，客户端正常断开不会把成功记录覆盖为 499。完成前客户端取消仍记录 499；写入或刷新失败仍记为失败。结算依据已取得的可靠用量，与响应是否成功送达分别判断。

## 请求诊断

「我的请求日志」在模型下方并列显示 API 协议和客户端实际使用的传输，例如 `Responses · WebSocket`。点击「请求诊断」可查看客户端到网关、网关到上游各段观测到的传输。HTTP SSE、HTTP JSON 和 WebSocket 按实际传输记录。无法确定响应格式时显示 HTTP，历史记录显示「未记录」。鉴权失败或被反向代理挡在网关外的请求可能没有日志。

诊断区分个人额度不足、个人并发限制、上游限流、协议不匹配和请求中断。可用时显示受限额度窗口、重置时间或建议重试时间。输出和完成状态反映网关观察结果，结算状态单独显示。已认证且被网关观测到的 WebSocket 握手失败可按请求 ID 查找；单独一条 SSE 日志无法确定客户端回退原因。「复制诊断」只复制请求 ID 和固定诊断字段，不包含上游原始报错、提示词或密钥。

分页和旧数组接口都可返回可选的 `diagnostics` 对象，包含 `protocol`、`client_transport`、`upstream_transport`、诊断 `code`、`retry_at`、`quota` 和发送、输出、完成状态。时间使用 Unix 秒。

## 结算异常

独立“待核算请求”页面与侧栏项已删除。管理员在请求日志选择“结算异常”后点击筛选：

- 详情：请求、用户、模型、原预占、状态、异常原因和价格快照。
- 重试结算：仅重试账本操作，不会重复调用上游。有可靠用量按原价快照结算，否则按 0 释放预占，操作前会确认。
- 人工核算：填写明确的 USD 金额和 3–200 字节依据；释放预占明确填 0，不接受省略/空金额。原请求窗口、账本、日志和审计原子提交。

只有 pending 记录允许重试/人工处理，在途记录不能人工结算。重试成功记录审计，重复重试已结算记录不会重复扣款；价格快照损坏或数据库异常则保留异常。即使当时日志写入失败，异常也可从账本显示；HTTP 状态显示“未记录”，不伪造成功/失败状态。恢复后不重复显示同一请求。

普通用户没有异常筛选和管理按钮，也不能调用管理员详情/结算 API；仍可看到自身日志的结算状态和原因。已删除的旧 `#charges` 书签跳转到日志页，管理员自动选择异常筛选。

## 自动结算

| 情况 | 本地额度处理 |
| --- | --- |
| 正常完成且有可靠用量 | 按请求的不可变价格规则及实际档位结算，释放预占差额 |
| 断流、取消、未完成但有可靠用量 | 按记录用量结算，释放预占并记录异常 |
| 缺失、不完整或无效用量 | 按零结算，释放预占并记录原因 |
| 请求未发出或上游明确拒绝执行 | 按零结算，释放预占 |
| 执行后发现档位或缓存价格缺失 | 按零结算，释放预占并保留用量、价格快照和原因 |
| 账本写入失败 | 保留证据、标记待核算并尽力释放预占；数据库无法写入时启动恢复继续处理 |

原始 token 不乘计费倍率。上游确认档位优先，未提供时使用请求档位并明确标记。缓存输入不重复收费，一小时缓存写入单独计价。可靠用量要求完整、非负的输入与输出；不会把缺失输出当成零，也不会在无效样本后使用此前样本猜测最终消耗。

先保存证据，再原子提交账本和日志金额。结算幂等，历史价格不变，人工核算不会被自动覆盖。释放后的待核算请求仍可按原来绑定的 5 小时/7 天窗口处理，不转扣新窗口。待核算证据不随普通日志清理。结算异常记录本身不会限制成员后续调用。

启动恢复只在单实例文件锁下、接受新请求之前运行，不重放上游模型请求。历史已结算账单不会追溯改账。管理员可在请求日志的结算异常中重试账本结算或填写实际金额人工核算；恢复旧记录时也适用上表规则。

本次使用模拟上游与临时数据库验证，未运行真实供应商计费验收。完整行为和限制见 [低维护账号共享](low-maintenance.md)。

## API

### 推理与速度参数

模型下方显示客户端请求的推理设置和速度档位：Codex Responses（含 WebSocket）的 `reasoning.effort`、Chat Completions 的 `reasoning_effort`，以及 Claude Code Messages 的 `output_config.effort`、`thinking.type`、`thinking.budget_tokens`、`speed`。各协议同时记录 `service_tier`，保留原始档位名称，不把不同厂商的档位或思考预算强行换算。

日志 API 增加可选字段 `reasoning_effort`、`thinking_type`、`thinking_budget_tokens`、`speed`、`service_tier`，分页和旧数组接口均返回这些字段。只提取顶层请求配置，不保存消息内容或逐消息配置。未指定、不可识别的参数与历史日志显示“未指定”；不会猜测模型默认值。记录的是账号策略调整前的客户端请求值，不代表上游最终采用的设置，也不是实测速率（tokens/s）。此功能仅观察参数，不改变请求转发和已有档位限制。

### 接口列表

- `GET /api/logs?page=1&page_size=20`：自己的日志。
- `GET /api/admin/logs?page=1&page_size=20&settlement=pending`：管理员结算异常。
- 可选 `model`、`request_id`、`status`、`since`；管理员还可选择 `settlement=pending/settled/inflight`。
- 分页返回 `{items,total,page,page_size}`。page 从 1 开始、最大 1000000，page_size 为 1–100，省略时分别默认 1/20。总数和页内容在同一读取事务内查询；翻页间新增记录可能改变后续页位置。
- 不传分页/结算筛选参数时保留旧数组接口（最多 200 条），旧 `before/before_id` 游标接口继续可用。
- `GET /api/admin/logs/{id}/settlement`：详情。
- `POST /api/admin/logs/{id}/retry-settlement`：重试，不产生新的推理请求。
- `POST /api/admin/logs/{id}/settle`：`{amount,reason}`，amount 为 microUSD；须管理员会话及 CSRF。
- 旧 `/api/admin/charges`、`/api/admin/charges/{id}/settle` 兼容保留。

日志不保存提示词、完整响应、上游 Key 或 SMTP 密码。费用策略见 [自动结算](request-logs.md#自动结算)。

### 管理员故障诊断

新发生的上游请求失败和客户端 WebSocket 握手拒绝同时写入容器/终端日志及管理员「运行日志」（模块 `gateway`，保留 7 天）。通过摘要中的 `request_id` 关联请求日志；握手拒绝保留连接数超限等具体原因。请求失败摘要包含账号（运行日志账号列）、尝试序号、传输、状态、是否发出/完成/观察到输出及固定故障分类。

原生 WebSocket 读取失败记录新建/复用连接、最后事件类别、关闭码（若收到）、超时或取消分类。不记录关闭原因原文、上游正文、URL、请求头或凭据；未收到关闭帧时可能只能确定读取失败，不能据此断言上游或代理的内部根因。此信息仅在升级后产生，不补录历史失败。Docker Compose 可用 `docker compose logs --timestamps --tail 200 fiftyapi` 查看。
