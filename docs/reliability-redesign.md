# 账号管理与网关可靠性

实现对照本地 sub2api 的账号生命周期、调度和网关协议，保留 FiftyAPI 的单实例 SQLite 与 5 小时/7 天金额账本。此版本不引入支付、套餐、商城或 Redis。

## 账号管理

- OAuth 添加/重新授权、API Key 上游接入、启停、改名、删除、连接与兼容配置、独立模型目录和同步时间。
- 批量导入 1–20 个授权 JSON 文件，合计不超过 1 MiB。支持 Codex auth.json 的 tokens、credentials 或平铺 token 字段；可选导入后验证，最多 4 个并行验证。文件中的地址、代理、请求头不会被信任；只接受必要授权字段，服务器加密保存。
- 导入成功与验证成功分别显示；未同步的授权不能进入模型路由；选择暂不验证的新导入账号不会被后台维护自动验证。临时模型目录故障保留最近成功目录，不把目录可见当作调用权限。
- 管理员可查看授权到期时间、能否自动刷新和 OpenAI 账号的必要身份摘要；不返回原始令牌。指定 workspace 可在账号连接配置中调整。
- 刷新按账号合并，先持久化轮换令牌再访问其他上游接口。等待刷新的人取消、401 后刷新时原请求取消，不会中断已开始的令牌轮换保存；拒绝刷新时显示需重新授权。
- 删除停止后续选路、删除模型关联/会话绑定、擦除当前数据库中的凭据和原名称。保留账号 ID 墓碑及财务历史引用，在途请求正常结算；不会撤销供应商侧授权，也不会改写旧备份。

## 调度

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| 优先级 | 50 | 0–100，较小的优先；不可用时选择其他账号 |
| 权重 | 1 | 同优先级且健康/负载相近时分配更多新会话 |
| 最大并发 | 5 | 1–100；仅在“调度与健康”编辑 |
| 等待队列 | 16 | 0–1000；0 表示不排队 |
| 单账号等待 | 2000 ms | 0–30000 ms；一次选路整体最多等待 10 秒 |

先按逻辑模型池筛选账号自己的上游模型映射、协议能力、启用状态、目录状态和冷却。优先级形成严格分层；同一优先级使用确定性加权抽样，长期新会话份额与账号权重一致。账号并发已满时才尝试下一候选。队列为有界 FIFO；取消会移除等待者和释放并发。队列出队后重新检查账号路由和用户/Key 状态。

会话健康时优先复用原账号，即使管理员随后调整了优先级；新会话立即使用新策略。绑定键包含用户、逻辑模型和协议，避免同一个客户端会话在不同模型池间误复用。完整可移植历史可在明确拒绝后切换；含签名、加密 reasoning、压缩状态或供应商侧工具上下文的历史保持原账号。绑定通过条件更新，避免并发请求互相覆盖，默认有效期 7 天。无法证明可迁移的上下文返回错误，不伪造签名。

一次逻辑请求最多 3 次尝试，**仅明确拒绝、尚未向用户输出实际内容、没有非零已知用量时**才允许重试。OAuth 401 可刷新后重试同一账号。普通 500、未知网络执行结果、部分输出、工具执行信号、客户端取消不重放。尝试阶段的初始化响应 ID 暂存，实际内容提交后禁止切换；最多缓冲 256 KiB。

## 健康、额度和日志

- 上游 Retry-After 和 Codex 双窗口头持久化；已耗尽窗口等待重置。明确耗尽但没有重置时间时短暂冷却，不把缺失数据当成零用量。
- 模型无权限/不支持仅冷却该账号的对应模型，不阻断其他模型。生成与 compact 分开记录。连续相关故障达到 3 次短暂熔断；成功请求不缩短已有冷却。
- “调度与健康”显示进行中/等待数、近期错误率、首个输出时间、最近成功/失败及上游额度快照。OpenAI 提供主动额度查询；其他平台没有实现通用主动查询，仅显示已获得的观测信息。
- 上游额度快照与用户美元预算独立，历史快照不保证实时剩余额度。管理员可以审计方式解除冷却，上游仍可能继续拒绝。
- 请求日志增加“路由详情”，显示每次账号、状态、耗时、首个输出及可枚举原因。普通成员只能查看自己的记录，管理员可查看全部。单次请求仍只预占/结算一次，不保存提示词、回复或凭据。旧日志可以没有尝试详情。

## Responses WebSocket

支持 `GET /v1/responses` 和 `/responses` 的原生上游 WebSocket；使用同一套用户认证、模型定价、调度、队列、预算、取消和逐次日志。OpenAI OAuth 默认可用；API Key 上游需在配置中显式开启 Responses WebSocket，且上游确实支持。失败不静默降为 HTTP。

支持 response.create、generate:false 预热、连接内 previous_response_id 延续和 stream_id 回传。一条下游连接对应独立原生上游连接，建立上下文后固定账号，不跨用户或连接借用响应 ID。连接断开后客户端需按错误指引发送完整历史；HTTP/SSE 继续采用 store:false 完整历史模式，不能借用连接内 ID。

限制：同一连接内顺序处理，最多 16 个等待 turn、32 个已登记 stream 名；多连接可并行。每用户最多 4 个连接，全局 128 个，连接最长 60 分钟。单帧请求 4 MiB、上游事件 2 MiB；单连接排队总大小 16 MiB、全局 128 MiB。不实现同连接内并行 stream、response.steer 或显式 response.cancel；关闭连接取消当前调用。停机先取消并等待连接结算、排空已开始的 OAuth 轮换，再关闭数据库。

规范参考：[OpenAI WebSocket mode](https://developers.openai.com/api/docs/guides/websocket-mode)。这些限制是本服务的实现范围，不代表 OpenAI 或 sub2api 的全部能力。

## 验收与升级

自动化覆盖 FIFO、权重、冷却持久化、明确拒绝切换、部分输出禁止重放、刷新合并与取消保存、导入隔离、删除防复活、成员隔离、原生 WebSocket 上下文与断开结算、停机排空。实际验收结果见 [兼容性](compatibility.md) 和 [OpenAI 记录](openai-acceptance.md)。Claude 缺少真实账号；真实 OAuth 轮换、新身份 compact、长时间原生代理工具工作流不冒充已验证。

升级启动自动执行迁移 008（schema 8）。停服并离线备份数据库、WAL/SHM 与原主密钥，保持原数据路径及密钥，再启动新版。不能让旧程序直接打开 schema 8；回滚必须恢复升级前完整备份。前端嵌入二进制，更新源码不会更新运行进程。步骤见 [部署文档](deployment.md)。

界面参考：[桌面调度与健康](screenshots/account-routing.png) · [手机调度表单](screenshots/account-routing-mobile.png)。截图使用模拟数据。

连接配置不再提供最大并发输入，也不再更新 account_policies.concurrency。旧配置接口的 max_concurrency 仅用于兼容读取，提交时忽略；并发仅通过调度策略接口修改。连接配置的旧表单不会覆盖后续并发调整。
